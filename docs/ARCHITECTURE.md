# Architecture

## Runtime split

```text
Android Activity (Kotlin)
  ├── Jetpack Compose menus / settings / touch UI
  ├── Android lifecycle, storage permissions and input routing
  └── NativeBridge (JNI)
        └── rustcraft-android (cdylib)
              └── rustcraft-game-core
                    ├── block identifiers
                    ├── chunk storage (16 x 384 x 16)
                    ├── deterministic terrain prototype
                    └── future world, physics and simulation systems
```

## Module boundaries

- `rustcraft-game-core` must remain platform-independent. Avoid Android, JNI and graphics APIs in this crate.
- `rustcraft-android` is the narrow FFI layer. Keep exported JNI methods small and validate all dimensions coming from Kotlin.
- Kotlin owns Android lifecycle, activity configuration, input delivery, storage APIs and Compose screens.
- A future renderer should consume chunk meshes generated by Rust. It should not put rendering state into the platform-independent world model.

## Current data model

- Chunk dimensions: 16 x 384 x 16.
- Vertical range: Y=-64 through Y=319.
- Surface map is a debug/top-down view only, not a 3D renderer.
- Block IDs are internal prototype IDs, not Java Edition registry IDs.

## Android ABI

CI currently builds `arm64-v8a` (`aarch64-linux-android`). Add `x86_64` only if emulator builds become a project requirement. The Rust library is loaded as `librustcraft_android.so`.
